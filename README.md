# summa-

PeerLearn is the world of skill trading: a lightweight student peer-learning MVP built
with React, Vite, Express, and SQLite.

## Scripts

- `npm --prefix server test` — run backend tests
- `npm --prefix client run dev` — start the frontend dev server
- `npm --prefix server run dev` — start the API in a separate terminal
- `npm --prefix client run build` — build the production frontend bundle
- `npm --prefix server start` — start the API and, in production mode, serve the frontend

## Local development

1. Copy `server/.env.example` to `server/.env` and set a private `JWT_SECRET`.
2. Start the backend with `npm --prefix server run dev`.
3. In another terminal, start the frontend with `npm --prefix client run dev`.
4. Open `http://localhost:5173`.

## Production run and deployment

Build the frontend with `npm --prefix client run build`, then start the server with
`NODE_ENV=production` and a `JWT_SECRET` of at least 32 characters. The server serves
the built app from `client/dist`; set `PORT` to the port provided by your host.
`GEMINI_API_KEY` is optional; without it, the AI helper uses its demo responses.

SQLite is suitable for a single-instance MVP only. For deployment, configure `DB_PATH`
to a writable, persistent disk location provided by the host; an ephemeral filesystem
can lose user data on restart or redeployment. Keep secrets out of source control.

### Deploying to Render

The root `render.yaml` defines a Render web service, production health check, generated
`JWT_SECRET`, and a 1 GB persistent disk mounted at `/var/data` for SQLite. The service
uses Render's `starter` plan because persistent disks require a paid web service. SQLite
is intended for this single-instance setup; do not scale the service to multiple
instances.

1. Push this project to a GitHub repository.
2. In Render, choose **New > Blueprint** and connect that repository. Render will read
   `render.yaml`; review the service and disk costs before applying.
3. After the service deploys, optionally set `GEMINI_API_KEY` in the Render environment
   if you want the AI helper's Gemini integration.
4. Open the deployed URL and confirm `/api/health` returns `{"ok":true}`.

Render deployment is not automatic until the repository is pushed and connected to a
Render account. Keep `JWT_SECRET` generated by Render and never commit local `.env` files.

## Learning and safety features

The subject directory includes Maths, Coding, Language, Music, Design, Video Editing,
and Generative AI, each with a subject-specific tips page. Tutors receive a printable
PeerLearn teaching certificate after the learner submits feedback for a completed
session; the certificate records the submitted star rating.

The Find page supports both tutor search and learner search. Tutors can offer to teach a
learner seeking help; the learner accepts or declines the offer. Profiles support an
editable, 240-character bio.

Accepted sessions include a participant-initiated safety report. There is no audio or
video monitoring. If `GEMINI_API_KEY` is configured, the report text is sent to Gemini
for a limited triage label; every report remains marked for human review, and AI output
does not establish whether an allegation is true. Without the key, the report is saved
for review but automatic triage is unavailable. Do not submit passwords or other
sensitive personal information.
